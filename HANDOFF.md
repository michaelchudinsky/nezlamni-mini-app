# Передача проекта NEZLAMNI Mini App

Этот файл нужен, чтобы другой разработчик мог быстро забрать проект и продолжить работу без поломки текущей версии.

## Что это за проект

NEZLAMNI Mini App - Telegram Mini App для gamified похудения, дисциплины и мотивации.

Главная механика:

- пользователь каждый день выполняет задания;
- получает баллы;
- видит прогресс дня, streak, профиль и рейтинг;
- участвует в месячном рейтинге и рейтинге новичков за первые 30 дней;
- постепенно открывает статусы профиля по общему количеству баллов.

## Технологии

- Next.js 16
- React 19
- TypeScript
- Tailwind CSS
- Supabase
- Vercel
- Telegram Bot / Telegram Mini App

## Как запустить локально

```bash
git clone https://github.com/michaelchudinsky/nezlamni-mini-app.git
cd nezlamni-mini-app
npm install
npm run dev
```

После запуска открыть:

```text
http://localhost:3000
```

Проверка перед сохранением изменений:

```bash
npm run build
```

## Какие файлы важные

- `app/page.tsx` - главный файл приложения: экраны, UI, задания, попапы, профиль, рейтинг, Shop-заготовка.
- `lib/supabase.ts` - подключение к Supabase.
- `supabase/migrations/*.sql` - SQL-файлы для изменений базы данных.
- `BETA_LAUNCH_TASKS.md` - список задач до беты и NEZLAMNI v2.
- `public/` - картинки, иконки и визуальные ассеты.
- `.env.local` - локальные ключи и токены. Этот файл нельзя коммитить.

## Переменные окружения

Нужны в `.env.local` локально и в Vercel Environment Variables:

```text
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
TELEGRAM_BOT_TOKEN=
CRON_SECRET=
TELEGRAM_MINI_APP_URL=
NEXT_PUBLIC_APP_URL=
```

`TELEGRAM_BOT_TOKEN` и `CRON_SECRET` нельзя отправлять в общий чат или коммитить в GitHub.

Миграции сейчас выполняются вручную через Supabase SQL Editor.

Важные SQL-файлы:

- `supabase/migrations/202605260002_create_reminder_deliveries.sql`
- `supabase/migrations/202605260003_add_public_profile_settings.sql`
- `supabase/migrations/202605260004_create_profile_supports.sql`
- `supabase/migrations/202606030001_create_reminder_cron_runs.sql`

Перед изменениями базы нужно:

1. Создать новый SQL-файл в `supabase/migrations`.
2. Показать Михаилу, что именно будет добавлено.
3. После подтверждения выполнить SQL в Supabase SQL Editor.
4. Проверить приложение.

## Важное про Telegram и Vercel

Рабочая версия в Telegram обновляется только после production deploy на Vercel.

Правило Михаила:

```text
Меняем и проверяем локально/в веб-версии.
В Telegram пушим только когда Михаил явно пишет: "пуш в тг".
```

Автоматические напоминания сейчас не считаются полностью готовыми. Причина: на Vercel Hobby есть ограничение cron, поэтому для 08:00, 15:00 и 21:00 нужен внешний cron-сервис, например `cron-job.org`, или Vercel Pro.

## Как работать с изменениями

- Делать маленькими шагами.
- Перед большими изменениями делать git checkpoint.
- Не удалять существующую логику без подтверждения.
- После каждого шага объяснять простыми словами, что изменилось.
- После изменений запускать `npm run build`.
- Не пушить в production без отдельного подтверждения Михаила.

## Что сейчас важно не потерять

В локальной папке могут быть несохраненные изменения:

- `app/page.tsx`
- `public/icons/camera-profile-v2.png`

Перед тем как Рома начнет активно менять проект, нужно решить: эти изменения коммитим, оставляем локально или откатываем.

## Ближайшие хорошие шаги

1. Доделать профиль пользователя:
   - изменение имени;
   - загрузка и изменение аватарки;
   - мотивационная фраза после обновления веса.
2. Доделать фото прогресса:
   - фото раз в месяц или каждые 30 дней;
   - согласие на хранение фото;
   - отдельное согласие на публичный показ;
   - баллы за фото.
3. Доделать Shop и монетизацию:
   - что будет бесплатным;
   - что будет premium;
   - что можно купить за баллы или деньги.
4. Вернуться к напоминаниям:
   - настроить внешний cron;
   - добавить диагностику в профиль;
   - проверить 08:00, 15:00 и 21:00.
5. Подготовить воронку марафона:
   - реклама;
   - Telegram-канал/чат;
   - бот;
   - Mini App;
   - бесплатная бета;
   - платный марафон.
6. Развить единую модель Lite + Pro:
   - Lite оставить доступным режимом ежедневной дисциплины и полезных привычек;
   - Pro сделать платной вкладкой внутри того же приложения;
   - в Pro добавить дневник питания, фотографию тарелки и ориентировочную калорийность;
   - показывать диапазон калорий и недельную динамику, а не обещать точный ежедневный дефицит;
   - не добавлять второй отдельный додаток до проверки спроса и удержания.

## Короткое правило

Если изменение касается только UI - можно делать локально и проверять через `npm run dev`.

Если изменение касается баллов, профилей, рейтинга, фото, напоминаний или базы данных - сначала обсудить план и только потом менять.
